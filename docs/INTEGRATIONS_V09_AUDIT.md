# v0.9 接入审查与修复记录

本轮目标：明确通知是否真正启用、前台朗读具体日程、定位刷新可诊断、飞书只读授权、工作台内播放。保留现有黑色风格、五卡片布局和横向全天日历。

## 通知

实际云端健康接口返回 200，说明服务可访问，不能证明某台 iPad 已授权、已订阅或已收到通知。当前运行环境缺少 Railway SSH 密钥，未读取服务数据库；未声称用户配对成功或失败。

发现：原前端仅通用文字，填码不等于开启订阅，重要提醒默认关闭，健康连接时停止前台备用提醒，网易云 iframe 只要载入就抑制语音。修复候选：工作台状态入口，权限/配对/提醒/免打扰/本次语音诊断，服务端每设备任务计数，前台独立提醒与去重，具体日程名称朗读，手动测试。日程名称不传给通知服务器；语音由系统 SpeechSynthesis 处理。重要提醒可临时降低本地音频音量并恢复；网页无法控制网易云 iframe 或原生 App 音量。

限制：iPadOS Web Push 不具备后台 SpeechSynthesis；锁屏仍为系统通知和系统声音，不能承诺后台朗读任意文字。免打扰、编辑保护保留。后台内容仍通用，不上传日程标题。

## 天气

发现：没有逆地理编码，所以界面不会显示具体地名；定位与网络失败提示不明确；刷新可能使用旧位置。

修复候选：maximumAge=0，高精度请求后有限网络定位重试；区分拒绝、超时、设备无位置、天气服务失败；清除时取消未完成请求；显示数据时间与设备报告精度。用户可在界面单独勾选 BigDataCloud 地名解析（会发送当前设备坐标，默认未勾选）。Open-Meteo 查询只发送近似坐标。另有明确标为「手动」的地区搜索备用入口，不冒充设备定位。位置及选择仅留本页内存。不会保证 Wi-Fi iPad 的街道/门牌精度。

## 飞书

保留并审查工作区已有 feishu-service / feishu.js / calendar.js 的只读候选。网关使用 OAuth state+PKCE、一次性领取、服务端加密令牌与刷新；网页不持有飞书令牌。合并只读日程，不写回飞书；本机重要标记独立，关闭后不再同步。

用户已创建应用并提供 App ID；App Secret 尚未配置，真实连接未完成。需要在既有 Railway 账号新建独立飞书服务、持久存储及稳定加密密钥，设置 PUBLIC_URL、FEISHU_APP_ID、FEISHU_APP_SECRET、TOKEN_ENCRYPTION_KEY。此服务不能借用其他项目凭据。随后在飞书配置精确回调 `/oauth/feishu/callback`、用户身份只读权限 `calendar:calendar:readonly`、`offline_access`、应用可用范围/版本发布，再由用户点击 OAuth 授权。不得把 Secret 发到聊天或前端。

浏览器控制读取飞书控制台多次超时，目前无法代用户操作账号内页面。可以继续通过用户填写私有变量及官方控制台配置完成授权。

## 媒体

本地音频移到工作台：原生 audio 进度/播放暂停、上一首/下一首、用户导入 LRC 同步歌词。官方网易云 iframe 移到同一音乐卡片，成功载入后关闭配置对话框。曲目/歌词/播放权限仍由官方播放器决定，不将 iframe 载入描述为正在播放。原生网易云 App 状态不可从该网页读取，不能承诺其歌曲、切歌和歌词实时镜像。网页播放仍需初次用户点击，导入音频/歌词并非自动网易云账号同步。
