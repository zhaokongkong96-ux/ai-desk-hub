# AI Desk Hub 工作台演进路线

日期：2026-10-30。

状态：用户明确认可下列五项均有投入价值；本文件将其纳入产品路线并给出建议交付顺序。路线确认不等于功能已经实现，也不表示已批准具体模型、费用、数据上传或本轮新增公开发布。

## 目标与基线

让工作台更好地支持开工、推进、收工和外出记录：少重复录入，清楚下一步，提前准备明天。

沿用已发布 v0.11.1 的居中大时钟、左记录、右待办、下方全天日程与地平线背景。新功能使用现有“今日重点”、待办和底部记录入口，默认收起、按需展开；不新增一排常驻卡片。保留日历、话题、热榜、音乐、本机数据及现有连接方式。

五项范围：每日固定流程、明日准备简报、智能收集入口、重复任务与项目清单、手机录入与工作台查看。多来源日历扩展不在本次用户圈定的五项之内。

## 第一批：每日执行与收工准备

包含每日固定流程、明日准备简报、重复任务与项目清单。以本机规则实现，先完成从开始到结束的日常使用，不依赖模型。

### 每日固定流程

- 提供可编辑的“开工、创作、收工”模板，每套默认 3—5 步。
- 建议模板仅作为可修改的初始内容，不代表用户已经制定了这些习惯。
- 开工示例：查看今日日程 → 选定最多三项重点 → 开始当前事项。
- 创作示例：选题 → 整理材料 → 写作 → 检查。
- 收工示例：整理未完成事项 → 保存今日记录 → 查看明日准备。
- 展开后突出当前一步，可完成、跳过、返回；允许中断后恢复，不以停留时长判断完成。

验收：编辑模板、执行一套流程、中途刷新继续；北京时间跨日后出现新一轮，昨日完成记录保持可追溯；未完成事项不会被清空或擅自标记完成。

### 重复任务与项目清单

- 第一版支持每天、每周指定日期；不先做复杂排程语言。
- 重复任务区分模板和某日实例，当天完成不取消以后的任务。
- 项目清单支持手动拆分步骤、逐项完成及完成数进度，例如汇报的“资料—结构—图表—检查”。
- 流程、重复任务与现有待办关联，避免同一事项生成多个互不关联的副本。

验收：日/周实例不重复生成，刷新与离线恢复后完成状态一致；修改某次任务与修改后续模板有清楚区分；项目步骤与进度一致；旧待办、笔记和日程仍可使用。

### 明日准备简报

- 在现有“今日重点”入口中切换“今日 / 明日”，不另起一个常驻简报面板。
- 显示明天第一项安排、后续关键日程、明确关联的准备材料、尚未完成的重要待办。
- 准备材料来自用户填写或确认过的导入内容；缺少材料时显示“未填写”，不臆造需求。
- 只有两个有明确起止时间的真实日程相交时提示冲突；时间未知的任务不冒充冲突。
- 区分本机/外部来源和读取状态；示例日程不进入真实准备清单。
- 内容可由本机规则生成，明确标注；不将没有截止时间的待办说成“明天到期”。

验收：北京时间今日/明日跨日正确；没有安排显示真实空状态；冲突能定位到具体事件；缺失信息不被补造；外部日历不可用时说明覆盖范围，不声称“明天无安排”。

## 第二批：通知到草稿再到日程

包含智能收集入口。先支持粘贴文字，之后评估图片/PDF；文本规则解析与模型识别分别标明能力。

流程：粘贴通知 → 提取事项/时间/准备材料 → 展示可编辑草稿 → 用户确认 → 写入日程或待办。

- 复用底部记录入口，以展开编辑器承载长文本和草稿。
- 明确绝对日期、相对日期的解释基准和北京时间；含糊日期、缺少时长或多种可能的时间标为待确认。
- 草稿保留与原始片段的对应关系，批量内容可逐项选择；重复导入给出已有记录候选，不重复创建。
- 未确认前不写入日历、正式待办或外部服务；保存失败时保留草稿供重试。
- 只把确认后的必要字段写入目标记录，私人通知和来源不进入公开仓库、静态 feed 或运行日志。
- 接入真实模型、OCR 或外部文件处理前，明确数据去向、服务、费用和调用范围；现有免费托管约束继续有效。

验收：明确通知可形成可编辑草稿；含糊通知能暴露缺项；取消不生成记录；重复点击确认不会重复创建；日程和待办能回到来源核查。图片/PDF不在纯文字第一版的完成口径内。

## 第三批：手机与桌面同一份数据

包含手机录入、工作台查看。先支持自己的设备之间同步，不扩大为多人家庭协作。

- 手机沿用同一个轻量记录入口；记录、待办可从手机进入工作台，并可在手机看到保存状态。
- 需要专用、受保护的数据同步机制；公开 GitHub Pages 只承担前端，不存储私人记录；不复用无关项目的数据或服务。
- 先完成记录、待办和本路线新增流程数据的同步；外部日历仍走既有只读链路，不顺带增加写回权限。
- 区分已保存到本机、等待同步、已同步、同步失败。明确同步延迟，不把刷新页面或本地存储等同于多端同步。
- 离线编辑可恢复；两端修改同一记录时能展示冲突供选择；删除不会被另一台旧设备悄悄恢复。
- 旧本机记录导入前可预览和备份，以稳定 ID 去重，不静默覆盖。身份验证与托管方案在实施前单独选定，保持免费约束。

验收：用两台独立设备或独立浏览器身份验证录入、更新、删除及双向状态；断网重连不丢数据、不重复；未配对设备无权读取；解除连接后访问失效。桌面模拟通过与真实手机/iPad验收分别记录。

## 交付和验证

每一批都先给出本地可操作版本，再验证旧记录兼容、核心交互、响应式显示及失败状态。公开发布记录说明完整包含的已确认视觉和功能，避免再次遗漏最新布局。

本路线的完成标准是能完成具体流程并保留真实状态，不以新增入口、占位按钮或测试数量代替功能交付。
